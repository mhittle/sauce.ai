================================================================
sauce.ai/news — install on GoDaddy Web Hosting Plus (cPanel)
================================================================

This is the *first-time* setup. CI/CD syncs the repo via FTP to
the account on every push to `main`. The code lands at:

    /home/YOURACCOUNT/public_html/sauce.ai/news/

Notation in this doc:
    YOURACCOUNT       = your cPanel username (e.g. lt1ih6uyy2z6)
    YOURACCOUNT_news  = example DB name; yours will differ
    $ ...             = command in cPanel Terminal


------------------------------------------------------------------
0. PREREQS
------------------------------------------------------------------
- cPanel access with SSH/Terminal enabled (or "Setup Python App"
  -> "Enter to the virtual environment" works for every command).
- An Anthropic API key (https://console.anthropic.com). Without
  one the classifier degrades to rules-only; the site still works.

Verify CI/CD has landed the code:
    $ ls /home/YOURACCOUNT/public_html/sauce.ai/news/passenger_wsgi.py
If that prints the path, you're ready.


------------------------------------------------------------------
1. CREATE THE DATABASE
------------------------------------------------------------------
1a) cPanel -> "MySQL Databases".
1b) Create a database:           YOURACCOUNT_news
1c) Create a user (strong pw):   YOURACCOUNT_newsuser
1d) Add the user to the database with ALL PRIVILEGES.

1e) phpMyAdmin -> select the new DB -> "Import" ->
    upload  news/seed/schema.sql  -> Go.

1f) Same again with  news/seed/feature_catalog.sql .


------------------------------------------------------------------
2. CREATE THE PYTHON APP
------------------------------------------------------------------
2a) cPanel -> "Setup Python App" -> "Create Application":

        Python version:        3.11 (or whichever 3.x is offered)
        Application root:      public_html/sauce.ai/news
        Application URL:       sauce.ai/news
        Application startup:   passenger_wsgi.py
        Application entry pt:  application

    Click "Create". cPanel will create the venv at:
        /home/YOURACCOUNT/virtualenv/public_html/sauce.ai/news/3.11/

    Important: Application root must be `public_html/sauce.ai/news`
    (not `sauce.ai/news`). The FTP deploy lands code under
    public_html/. Mismatch between Application root and code
    location is the most common cause of a 500 / fork-bomb on
    boot.

2b) On the app's page, click "Edit" and add environment variables.
    Generate a real SECRET_KEY first; do NOT paste the placeholder.
    In Terminal:

        $ python3 -c "import secrets; print(secrets.token_hex(32))"

    Then set in cPanel:

        SECRET_KEY              <output of above>
        DB_HOST                 localhost
        DB_PORT                 3306
        DB_USER                 YOURACCOUNT_newsuser
        DB_PASSWORD             <password from step 1c>
        DB_NAME                 YOURACCOUNT_news
        ANTHROPIC_API_KEY       <your key, or blank for rules-only>
        ANTHROPIC_MODEL         claude-haiku-4-5-20251001
        ADMIN_EMAIL             your-email@example.com

    Optional (only required if you enabled the daily email digest cron in §4):
        SITE_URL                https://sauce.ai/news
        SMTP_HOST               localhost      (cPanel's local MTA; or relay host)
        SMTP_PORT               25             (use 587 with SMTP_USE_TLS=1 for a relay)
        SMTP_USE_TLS            0              (1 for STARTTLS)
        SMTP_USER               <blank for localhost>
        SMTP_PASSWORD           <blank for localhost>
        SMTP_FROM               news@sauce.ai
        DIGEST_MAX_ARTICLES     8
        DIGEST_LOOKBACK_HOURS   24

    Do NOT set APPLICATION_ROOT. LiteSpeed/Passenger already
    mounts the app at /news via the "Application URL" setting;
    setting APPLICATION_ROOT in env vars causes a double-prefix
    bug where every URL returns 404.

    Do NOT commit a .env to the repo. cPanel env vars are canonical.

2c) On the same page, copy the "Enter to the virtual environment"
    command. It looks like:

        source /home/YOURACCOUNT/virtualenv/public_html/sauce.ai/news/3.11/bin/activate \
        && cd /home/YOURACCOUNT/public_html/sauce.ai/news

    Run it in Terminal, then:

        $ pip install -r requirements.txt

    If `feedparser` -> `sgmllib3k` fails to build, run:
        $ pip install --no-build-isolation feedparser
    first, then re-run pip install.

2d) Sanity-check the interpreter before letting Passenger
    touch it (skipping this step is how you trigger the
    fork-spawn loop):

        $ /home/YOURACCOUNT/virtualenv/public_html/sauce.ai/news/3.11/bin/python \
          -c "import sys, flask, pymysql, anthropic; print(sys.version.split()[0], 'ok')"

    Expected output is one line like `3.11.14 ok`. If it
    instead prints "No such file or directory" for `activate`,
    `set_env_vars.py`, or `python_bin`, the venv shim is broken
    -- destroy the Python App and recreate it before continuing.

3b) Visit https://sauce.ai/news/ . You should see the feed page

3f) https://sauce.ai/news/admin/feeds -> click
    "Import / refresh seed CSV". Loads ~135 seed sources.

4. CRON JOBS
------------------------------------------------------------------
Before adding the cron jobs in cPanel, validate from Terminal
that one run works end-to-end. cPanel cron does NOT source the
venv automatically, so every cron line must `source activate`
itself before invoking python.

4a) Test the diagnostic from a fresh shell:

        $ source /home/YOURACCOUNT/virtualenv/public_html/sauce.ai/news/3.11/bin/activate \
          && cd /home/YOURACCOUNT/public_html/sauce.ai/news/jobs \
          && python _selftest.py

    Every line should print PASS. If MySQL connect fails, the
    env vars from step 2b aren't being passed through -- fix
    that before adding cron entries.

4b) Test fetch_feeds once by hand:

        $ python fetch_feeds.py

    Should print a summary like `fetched=80 fresh=300 stale=20`.
    Run classify_pending.py once after that.

4c) cPanel -> "Cron Jobs". Add four entries, replacing
    YOURACCOUNT in each line:

# every 15 min: fetch RSS feeds
*/15 * * * *  source /home/YOURACCOUNT/virtualenv/public_html/sauce.ai/news/3.11/bin/activate && cd /home/YOURACCOUNT/public_html/sauce.ai/news/jobs && python fetch_feeds.py >> /home/YOURACCOUNT/public_html/sauce.ai/news/logs/cron.log 2>&1

# every 5 min: classify pending articles
*/5  * * * *  source /home/YOURACCOUNT/virtualenv/public_html/sauce.ai/news/3.11/bin/activate && cd /home/YOURACCOUNT/public_html/sauce.ai/news/jobs && python classify_pending.py >> /home/YOURACCOUNT/public_html/sauce.ai/news/logs/cron.log 2>&1

# every 30 min: popularity poll
*/30 * * * *  source /home/YOURACCOUNT/virtualenv/public_html/sauce.ai/news/3.11/bin/activate && cd /home/YOURACCOUNT/public_html/sauce.ai/news/jobs && python popularity_poll.py >> /home/YOURACCOUNT/public_html/sauce.ai/news/logs/cron.log 2>&1

# nightly 3:30am UTC: prune + reputation refresh
30  3 * * *   source /home/YOURACCOUNT/virtualenv/public_html/sauce.ai/news/3.11/bin/activate && cd /home/YOURACCOUNT/public_html/sauce.ai/news/jobs && python maintenance.py >> /home/YOURACCOUNT/public_html/sauce.ai/news/logs/cron.log 2>&1

# daily 12:00 UTC: personalized email digest (only adds value once users opt in)
0   12 * * *  source /home/YOURACCOUNT/virtualenv/public_html/sauce.ai/news/3.11/bin/activate && cd /home/YOURACCOUNT/public_html/sauce.ai/news/jobs && python send_digest.py >> /home/YOURACCOUNT/public_html/sauce.ai/news/logs/cron.log 2>&1

# hourly: source discovery harvest (Reddit/HN domain mining)
15  * * * *   source /home/YOURACCOUNT/virtualenv/public_html/sauce.ai/news/3.11/bin/activate && cd /home/YOURACCOUNT/public_html/sauce.ai/news/jobs && python discover_harvest.py >> /home/YOURACCOUNT/public_html/sauce.ai/news/logs/cron.log 2>&1

# nightly 4:00am UTC: source discovery validation (RSS auto-discovery on pending candidates)
0   4 * * *   source /home/YOURACCOUNT/virtualenv/public_html/sauce.ai/news/3.11/bin/activate && cd /home/YOURACCOUNT/public_html/sauce.ai/news/jobs && python discover_promote.py >> /home/YOURACCOUNT/public_html/sauce.ai/news/logs/cron.log 2>&1

# weekly Monday 5:00am UTC: LLM-suggested source discovery (uses Anthropic API)
0   5 * * 1   source /home/YOURACCOUNT/virtualenv/public_html/sauce.ai/news/3.11/bin/activate && cd /home/YOURACCOUNT/public_html/sauce.ai/news/jobs && python discover_llm.py >> /home/YOURACCOUNT/public_html/sauce.ai/news/logs/cron.log 2>&1

# every 30 min: external trending poll (Google Trends + Google News RSS)
*/30 * * * *  source /home/YOURACCOUNT/virtualenv/public_html/sauce.ai/news/3.11/bin/activate && cd /home/YOURACCOUNT/public_html/sauce.ai/news/jobs && python trending_poll.py >> /home/YOURACCOUNT/public_html/sauce.ai/news/logs/cron.log 2>&1

    Note: output is redirected to logs/cron.log (NOT /dev/null).
    If a cron job goes wrong you must be able to see the error.
    Tail with:  $ tail -100 ~/public_html/sauce.ai/news/logs/cron.log

    The digest cron is harmless before anyone opts in (it simply
    exits with `sent=0 candidates=0`). Add it now or after first
    opt-ins -- your call.

    The three discover_* jobs grow the source catalog automatically.
    discover_harvest mines new domains from Reddit/HN every hour;
    discover_promote runs RSS auto-discovery on the candidates with
    enough hits; discover_llm asks Claude weekly for high-quality
    feeds we don't yet have. Approve or reject candidates on
    /admin/discovery. The whole pipeline is gated behind admin
    review by default -- nothing lands in `sources` until you click
    Approve. If ANTHROPIC_API_KEY is unset, discover_llm exits as
    a no-op.

------------------------------------------------------------------
8. TROUBLESHOOTING
------------------------------------------------------------------
A. Site hangs or returns 404 on every URL, Passenger log shows
   thousands of "fork: Resource temporarily unavailable" plus
   "/activate: No such file or directory":

   This is the venv-shim fork-bomb. The CloudLinux python shim
   couldn't resolve its CWD and Passenger respawned in a tight
   loop, exhausting nproc. Two causes:
     1. Application root in cPanel doesn't match where CI/CD
        deployed code (i.e. you set `sauce.ai/news` instead of
        `public_html/sauce.ai/news`).
     2. Stale Python App entry still configured at the wrong
        path. Only ever have ONE Python App per URL.

   Recovery: "Stop App" in cPanel, then
       $ pkill -u YOURACCOUNT -f python ; sleep 5 ; \
         pkill -9 -u YOURACCOUNT -f python
   Wait 60s. `ps -ef | grep ^YOURACCOUNT | wc -l` should drop
   to single digits. Then destroy + recreate the Python App with
   the correct root (step 2a).

B. Site returns 404 with a clean Passenger log:

   You set APPLICATION_ROOT=/news in cPanel env vars. Don't.
   LiteSpeed already mounts the app at /news; Flask then
   double-prefixes and 404s every request. Remove the env var
   (or set it to `/`) and Restart.

C. Cron jobs silently do nothing:

   Every cron line must `source activate` before running python,
   and must redirect output to logs/cron.log (not /dev/null).
   Run jobs/_selftest.py from a fresh shell with the activate +
   cd combo above to see exactly which check fails.

D. fork: Resource temporarily unavailable on every command:

   You've hit your CloudLinux nproc/EP limit. Stop the Python App,
   pkill your python processes, wait 2 minutes, open a fresh
   Terminal. If it persists, contact GoDaddy support to raise
   the EP limit (Web Hosting Plus defaults around 20-30 EPs).

E. "Module not found: app":

   Application root in Setup Python App is wrong. Must be
   `public_html/sauce.ai/news`, not `public_html/sauce.ai`.

F. Articles never get popularity > 0:

   Normal. popularity_poll only matches URLs that appear on
   Reddit / HN. Typical match rate ~5-10% after a week.

G. Code from a fresh git push isn't visible:

   "Setup Python App" -> "Restart". Passenger caches imports
   until restart, even after CI/CD writes new files.

H. Daily digest cron runs but no email arrives:

   Tail logs/cron.log -- the job logs `sent=N skipped_empty=M
   failed=K candidates=C`. If candidates=0, no users have opted
   in yet (toggle on /account/settings). If failed>0, check the
   exception trace for SMTP errors. cPanel's local MTA on port
   25 is usually unauthenticated and silently drops messages
   destined for inboxes that don't trust the shared IP -- if
   deliverability is poor, set SMTP_HOST / SMTP_USE_TLS=1 /
   SMTP_USER / SMTP_PASSWORD to a real relay (Postmark, SES,
   Mailgun) instead.

I. /admin/discovery is empty even though discover_harvest is running:

   Three things to check.
   1. The hourly harvest only logs candidates whose domains aren't
      already in `sources`. With 768 seed sources already in the
      table, most Reddit/HN URLs already map to a known domain.
      Single-digit `candidates_upserted` per tick is normal.
   2. The "Ready to review" section only shows rows after the
      nightly `discover_promote` job runs RSS auto-discovery and
      sets state='validated'. Pending rows below score
      DISCOVER_PROMOTION_SCORE_MIN (default 3) won't be probed
      until they hit the threshold.
   3. discover_llm only runs on Mondays at 05:00 UTC and requires
      ANTHROPIC_API_KEY. Tail logs/cron.log for the run output;
      if it printed "ANTHROPIC_API_KEY not set; skipping" the
      env var isn't reaching the cron environment.


J. Trending sort is empty / still looks like the old HN-only feed:

   1. The `trending` column migration
      (2026-05-17-trending.sql) must be applied and the Python App
      restarted. Until then `/?sort=trending` errors on the missing
      column (other sorts are unaffected).
   2. `trending_poll` must have run at least once. Tail
      logs/cron.log for its line:
      `topics=T gnews=G articles=N matched=M`. matched=0 with
      topics>0 means nothing in the rolling window matched a hot
      topic (possible briefly after deploy). topics=0 means Google
      throttled the RSS this tick -- non-fatal, the job writes
      trending=0 and the feed falls back to algo order; it
      self-heals next tick.
   3. trending decays: the job rescores only the last
      TRENDING_WINDOW_DAYS (default 2) of articles each tick, so
      older articles correctly drop out of the Trending sort.

9. SECRETS HYGIENE
------------------------------------------------------------------
- API keys and DB passwords live only in cPanel "Setup Python
  App" env vars. NEVER paste them into chat tools, screenshots,
  or commits.
- If you suspect a key was exposed, rotate immediately:
    Anthropic: console.anthropic.com -> API Keys -> revoke.
    MySQL pw:  cPanel -> MySQL Databases -> change password,
               then update cPanel env var, then restart app.
- The repo's `.htaccess` only carries env vars; cPanel writes
  it. Treat that file as sensitive even though it's not in the
  repo.

10. KNOWN v1 LIMITATIONS
------------------------------------------------------------------
- "Your Algo" Code tab renders the Python equivalent of the
  UI-chosen weights but does not execute user-supplied code.
  Sandboxed exec deferred to v2.
- No CSRF tokens beyond same-site cookies, no email verification,
  no rate limiting on auth endpoints.
- Body extraction (article_bodies) runs in classify_pending and is
  wallclock-bounded, so deploys must apply the
  2026-05-13-article-bodies.sql migration. Locked paywalls (score 1.0)
  are skipped; everything else gets a row with status ok/empty/blocked/
  error. Pruned nightly at BODY_RETENTION_DAYS (default 30).
- Internal click signal is recorded but not folded into popularity.
- Daily email digest sends from the configured SMTP_FROM with no
  DKIM/SPF setup by default. Deliverability on shared cPanel IPs
  is mixed; configure a relay (SMTP_HOST + SMTP_USE_TLS=1 + creds)
  via cPanel env vars if first-send tests land in spam.
- Automated source discovery (Reddit/HN + LLM agent) is gated
  behind admin review on /admin/discovery. Approved candidates
  land in `sources` with default source_lean=0,
  source_reputation=0.6, country=US, region=national; tune those
  on the row directly via the admin form before approval. Social-
  firehose discovery (Mastodon, Bluesky, X/Twitter) is roadmapped
  but not in v1.
- Article deduplication clusters byte-identical reprints (via
  title_hash) and minor re-headlines of identical bodies (via
  64-bit SimHash, Hamming<=8). Heavy paraphrases of the same
  story do not cluster; an embedding-based v2 pass is on the
  roadmap. Firehose is intentionally NOT deduped.
- English-only article filter runs in fetch_feeds, three stages:
  (1) trusts an RSS feed's <language> tag when it declares
  non-English (e.g., ja, de-DE); (2) rejects on >25% non-Latin
  letter ratio in title+summary (CJK, Arabic, Cyrillic, Hebrew,
  Devanagari, Thai, etc.); (3) py3langid on the remaining
  Latin-script text catches French/German/Spanish/Italian/
  Dutch/Finnish/etc. that stage 1+2 miss (BUG-013). Stage 3 is
  deliberately conservative: text under 24 Latin letters, or a
  low-confidence / English-plausible call, is kept — dropping a
  real English article is a worse regression than an occasional
  foreign one slipping through. Detector failures fall through
  to accept (never breaks the fetch loop). py3langid was chosen
  over langdetect (BUG-014) because it ships a prebuilt wheel —
  langdetect 1.0.9 is sdist-only and fails to build on the cPanel
  venv. Per-tick rejection count surfaces in cron.log as
  `skipped_lang=N`.
- The "Trending" feed sort (formerly "Popularity") is driven by
  `article_features.trending`, filled by the trending_poll cron
  from Google Trends + Google News RSS. Article-to-topic matching
  is token-overlap only: it is NOT entity/synonym aware, so e.g.
  "Fed" will not match a "federal reserve" trend, and paraphrased
  headlines under-match. Good enough for v1 surfacing; the
  entity-extraction upgrade is shared with the roadmapped Trending
  topics view / Signal Learning work. The sort still applies the
  user's algorithm as the within-trending tiebreak, and legacy
  `?sort=popularity` URLs are aliased to it.
